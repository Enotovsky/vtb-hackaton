# ВТБ Семья — объединённый проект

Дизайн из архива от 22 октября подключён к FastAPI и SQLite. Интерфейс и API запускаются одним Python-сервером. Node.js для работы не нужен. Все деньги виртуальные; реальные платежи и API банка не подключены.

## Быстрый запуск на macOS

Нужен Python 3.10 или новее. Распакуйте архив целиком в новую папку, откройте Терминал в папке `VTB-family` и выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py
```

Откройте **http://127.0.0.1:8000/?mobile=1**. Терминал должен оставаться открытым. Остановка — Ctrl+C.

Альтернативный запуск: `bash start-macos.command`. Скрипт создаст окружение, установит зависимости и запустит приложение. Он не требует глобальной установки FastAPI.

Повторный запуск после установки:

```bash
cd /путь/к/VTB-family
.venv/bin/python run.py
```

Если порт занят: `.venv/bin/python run.py --port 8001`, затем откройте адрес с портом 8001. Скрипт не завершает чужие процессы.
Не открывайте `frontend/index.html` двойным нажатием: интерфейсу нужен сервер.

## Windows

Запустите `start-windows.cmd` или выполните:

```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

Скрипты запуска подготовлены для macOS/Windows; автоматические проверки этого архива выполнены на Linux с Python 3.12. На macOS и Windows отдельно не запускались.

## Профили и данные

На первом запуске создаются Александр (организатор), Мария (ещё не приняла приглашение), Макс и Соня. Выберите профиль на экране входа. Для совместной проверки откройте две отдельные вкладки, выберите Александра и Марию. Сессии хранятся в sessionStorage каждой вкладки. В меню «Ещё» есть ссылка на второй вход.

Напоминания о секциях и карманных деньгах создаются после согласования детского плана. Готового самостоятельного напоминания о бассейне нет, чтобы не дублировать плановую оплату.

Общий счёт: 8 000 ₽; Макс: 0 ₽; Соня: 1 800 ₽; цель: 68 500 ₽. Это начальные тестовые остатки. Взносы в цель выполняются настоящим переводом между учебными счетами в SQLite. Личные остатки взрослых видны только соответствующему профилю.

Вход через исходный API тоже сохранён: `POST /api/auth/login`, `alex@test.ru` или `maria@test.ru`, пароль `demo2026`. Код ребёнка Макса: `MAX2026`. Эти реквизиты исключительно учебные.

База создаётся в `data/family_bank.db`. Перезапуск и `python seed.py` не стирают данные. «Ещё → Начать сценарий заново» сбрасывает денежную историю и планы только учебной семьи после подтверждения в интерфейсе; пользовательские семьи не затрагиваются. Сброс оставляет журнал событий, учётные записи, действующие сессии и созданные дополнительные счета с нулевым балансом.

Для нового полного набора демо можно остановить сервер и переместить всю папку `data` в резервную папку. При следующем запуске создастся новая база. Не делайте это на работающем сервере и не переносите в архив действующие пользовательские базы.

## Что подключено

- Приглашение, согласие, принятие/отказ, отмена, истечение и отзыв доступа.
- Совместный остаток, личные остатки, история и обновление второго экрана.
- Общий месячный бюджет с контролем версии.
- Детский план: черновик, отправка, согласование вторым взрослым, возврат и повторное согласование.
- Оплата расходов, личный взнос в общий счёт, перевод ребёнку и взнос в цель.
- Детская покупка с проверкой баланса, лимита и заморозки.
- Напоминания, безопасные HTTPS-ссылки, ручная отметка без списания.
- Заметки, новые общие счета, сохранение учебных предложений, поиск и аналитика.

Перевод ребёнку и вклад в цель не являются расходом семьи. Покупка ребёнка учитывается в расходах один раз. Карманные деньги из напоминания переводятся в детский кошелёк, а не списываются как покупка.

## API и структура

- Новый UI: `/`; документация API: `/docs`; доступность сервера: `/health`.
- API дизайна: `/api/ui/*`, реализован в `app/routers/ui.py`.
- Исходные эндпоинты `/api/*` сохранены, технический UI доступен по `/static/index.html`.
- `frontend/` — HTML, CSS, ES-модули, изображения. Дизайн и основные экраны сохранены.
- `app/` — FastAPI, SQLAlchemy, платежи, права, адаптер и дополнительные модели.
- `tests/` — исходные тесты, интеграционные проверки и отдельный браузерный сценарий.
- `run.py`, `seed.py` — запуск и безопасная инициализация.
- `docs/INTEGRATION.md`, `docs/TEST_RESULTS.md` — устройство интеграции и проверенные сценарии.

Отдельный Node.js API и JSON-хранилище из дизайнерского архива не используются: источником общих данных является SQLite.

## Тесты

```bash
python -m pytest -q
```

Ожидаемый результат для этой версии: **74 passed**. Тесты используют отдельную временную базу и не меняют `data/family_bank.db`.

Браузерные проверки:

```bash
python -m pip install -r requirements-test.txt
python -m playwright install chromium
python tests/browser_smoke.py
```

Тест сам запускает сервер на свободном порту с отдельной временной базой, проверяет три независимых входа и останавливает сервер. Установка браузера требует интернета. Скриншоты проверки сохраняются в `.build/browser/`.

## Границы версии

Это рабочий локальный учебный MVP, а не банковская платёжная система. Вход выбором имени специально упрощён. `run.py` включает `VTB_DEMO_MODE=1` и по умолчанию слушает только 127.0.0.1. Прямой запуск через uvicorn не включает учебные входы автоматически. `VTB_DEMO_MODE=0` отключает быстрые профили, имитацию отказа/задержки и сброс; полноценный пользовательский экран регистрации для такого режима не разработан.

Нет реальных банковских интеграций, отправки приглашения письмом, промышленной авторизации, срока жизни сессий, защиты от перебора, миграций Alembic, автоматической сверки зависших платежей, возвратов и полноценной модели полномочий законных представителей. Старые служебные методы метрик и баг-репортов предназначены только для локальной разработки, не для публичного размещения.

Если процесс аварийно завершится после записи pending, результат может остаться неопределённым. Повторный ключ не инициирует автоматическое новое списание: для такой ситуации нужна сверка с провайдером и отдельный обработчик восстановления. В тестовом контуре это ограничение явно сохранено.

При работе с напоминаниями план и отдельное вручную созданное дело являются разными объектами. Система не угадывает, относятся ли две похожие записи к одному обязательству. Убирайте из демо ненужное самостоятельное напоминание перед созданием одноимённого планового.

Публикация и развёртывание на family.genesis-digital.ru в рамках этой сборки не выполнялись.
