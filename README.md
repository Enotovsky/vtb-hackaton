# ВТБ · Семейный банкинг — MVP (спринт 1)

Бэкенд: FastAPI + SQLAlchemy + SQLite. Фронт — технический (`static/`), только чтобы руками проверить API; дизайнер сделает новый.
Все деньги тестовые, суммы в API в **копейках** (`150000` = 1 500 ₽).

## Запуск

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
python seed.py                # пересоздаёт базу и тестовую семью
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- UI: http://localhost:8000 (с телефона в той же Wi-Fi — `http://<IP-компьютера>:8000`)
- Swagger: http://localhost:8000/docs
- Тесты: `pytest -q` (43 теста, покрывают весь чек-лист спринта)

Тестовая семья (`seed.py`): `mama@test.ru` / `1234` (владелец), `papa@test.ru` / `1234`, дети Маша и Ваня;
код входа ребёнка печатает `seed.py` и показывает владельцу UI. Сессия хранится в `sessionStorage`,
поэтому **каждая вкладка браузера — отдельное устройство**.

## Что сделано (по задачам спринта)

| Задача | Где | Как устроено |
|---|---|---|
| Вход двух взрослых, серверная семья, права | `routers/auth.py`, `routers/family.py`, `core.py` | Токен-сессии на устройство. Членство проверяется **на каждом запросе** (`require_member`) → после выхода/удаления доступ пропадает сразу, карта на общем счёте блокируется. Составом (приглашения, удаление, дети) управляет только владелец. Максимум 2 взрослых. |
| Приглашения `sent/accepted/declined/expired/cancelled` | `routers/family.py` | Принять может только вошедший пользователь с тем же email. Переход `sent→accepted` — атомарный `UPDATE … WHERE status='sent'`; `UNIQUE(family_id,user_id)` — повторное принятие не создаёт участника. Истечение — лениво по `expires_at` (`ttl_seconds` для тестов). Старое приглашение не возвращает доступ удалённому. |
| Общий остаток и история | `routers/accounts.py` | `/api/family/operations`: дата, сумма, плательщик, назначение, ребёнок, карта. Карты привязаны к счёту (`cards.account_id`). Личные счета/операции партнёра не отдаются ни одним эндпоинтом (чужой счёт → 404). |
| Бюджет ребёнка по месяцам | `routers/budget.py` | Статьи: секция/кружок/карманные/другое, сумма, срок, сайт. `draft → pending_approval → approved / needs_revision`. Согласует **второй** взрослый. Изменение сумм → снова `draft`. Оптимистичная блокировка `version` → 409 вместо затирания. План деньги не трогает. |
| Тестовая оплата | `payments.py` | `Idempotency-Key` + `UNIQUE(payer,key)` — повтор возвращает тот же платёж. `pending` фиксируется до списания, затем `completed/failed`. Списание `UPDATE … WHERE balance >= amount` в одной транзакции, при ошибке — откат. В платеже и операции отдельно `payer_user_id` и `child_id`. `simulate_failure` — имитация отказа. |
| Кошелёк ребёнка | `routers/children.py` | Отдельный баланс, месячный лимит, заморозка; проверяются на сервере при покупке ребёнка (`/api/child/purchases`, вход ребёнка по коду). Использованный лимит = сумма покупок за месяц → пополнение его не сбрасывает; лимит не меняет баланс; оплата секции родителем идёт со счёта родителя и лимит не тратит. |
| Напоминания | `routers/budget.py` | Создаются при согласовании плана: ребёнок + статья + сумма + срок; после оплаты хранят `payment_id` и `operation_id`. Успешная оплата закрывает (`paid`), неуспешная — нет. «Сайт» и «Отметить вручную» остатки не меняют. |
| Журнал событий/метрики | `models.Event`, `/api/family/events`, `/api/metrics` | `family_created, invitation_*, member_removed/left, plan_created/updated/submitted/approved/returned, payment_completed/failed, reminder_*, child_*`. |
| Тестовая семья, 2 устройства | `seed.py`, `docs/DEMO_SCENARIO.md` | |
| Негативные проверки | `tests/`, `docs/DEMO_SCENARIO.md` | Двойные нажатия (в т.ч. параллельные), нехватка денег, заморозка, лимит, просроченное приглашение, отзыв доступа. |
| Учёт ошибок | `/api/bugs` + форма в UI, `docs/BUGS.md` | Шаги, ожидаемый, фактический результат, скриншот (`uploads/`). |

## Структура

```
app/
  main.py          приложение, статика
  db.py, models.py БД и модели
  core.py          ошибки, пароли, сессии, проверка прав, log_event
  payments.py      проведение платежей (идемпотентность, атомарность)
  serializers.py   что именно отдаём наружу
  routers/         auth, family (+приглашения, дети), accounts (+платежи), children, budget (+напоминания), events (+метрики, баги)
static/            технический UI
tests/             pytest
seed.py            тестовая семья
docs/              сценарий демо и баг-лист
```

## Ограничения MVP

- SQLite; для прода — PostgreSQL (вместо «блокирующего» UPDATE в покупке ребёнка сработает `SELECT … FOR UPDATE`, он уже стоит в коде).
- Приглашение не отправляется письмом — владелец копирует ссылку из UI.
- Нет миграций (Alembic) — при изменении моделей пересоздать базу `python seed.py`.
