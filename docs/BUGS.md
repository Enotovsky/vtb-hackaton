# Баг-лист

Основной способ — форма «Сообщить об ошибке» в UI (`POST /api/bugs`, скриншот сохраняется в `uploads/`, список — `GET /api/bugs`).
Здесь — шаблон и ошибки, найденные при прогоне сценария.

## Шаблон

```
### BUG-N: <кратко>
Статус: open | fixed
Шаги:
1. ...
Ожидаемый результат: ...
Фактический результат: ...
Скриншот: uploads/<файл>.png
```

---

### BUG-1: В журнале событий ребёнок записывался как «автор» действия
Статус: fixed
Шаги:
1. Родитель пополняет кошелёк ребёнка или оплачивает расход с привязкой к ребёнку.
2. Открыть «Журнал событий».

Ожидаемый результат: автор — родитель, `child_id` — в данных события.
Фактический результат: `child_id` попадал в поле «актор» события, в payload его не было — метрики по детям были бы неверны.
Исправление: `log_event(..., actor_child_id=...)` отделён от `child_id` в payload (`app/core.py`).

### BUG-2: Старое приглашение отвечало «уже принято» после удаления участника
Статус: fixed
Шаги:
1. Владелец удаляет второго взрослого.
2. Удалённый нажимает «Принять» в старом (принятом) приглашении.

Ожидаемый результат: понятный отказ, доступа нет.
Фактический результат: `200 {"already": true}` — UI показывал «приглашение уже принято», хотя доступа нет.
Исправление: такой запрос возвращает `409 invite_used`; кнопка «Принять» показывается только для `sent`.
Тест: `tests/test_family.py::test_old_invite_does_not_restore_access_after_removal`.

### BUG-3: «Сохранить» без изменений поднимал версию плана
Статус: fixed
Шаги:
1. Открыть план, ничего не менять, нажать «Сохранить».

Ожидаемый результат: ничего не происходит, версия и статус прежние.
Фактический результат: версия росла, в журнал писалось `plan_updated`. Второй взрослый, открывший план раньше, получал конфликт версий при согласовании.
Исправление: сервер сравнивает поля и при отсутствии изменений возвращает `changed: false` без записи; UI пишет «Изменений нет». Номер версии убран с кнопки.
Тест: `tests/test_budget.py::test_save_without_changes_keeps_version_and_status`.

### BUG-4: В интерфейсе родителя нельзя проверить оплату с кошелька ребёнка
Статус: fixed
Шаги:
1. Войти взрослым, открыть «Дети и виртуальные кошельки».

Ожидаемый результат: есть тестовая покупка с баланса ребёнка.
Фактический результат: покупка была только в режиме ребёнка (вход по коду), и её было сложно найти.
Исправление: `POST /api/children/{id}/test-purchase` и блок «Тестовая покупка с кошелька ребёнка» в карточке. Логика и проверки те же, что у покупки ребёнка.
Тест: `tests/test_child_wallet.py::test_parent_test_purchase_uses_same_checks`.
