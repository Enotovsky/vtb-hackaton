# Как соединены части проекта

FastAPI раздаёт `frontend/index.html` и ресурсы напрямую. Браузер загружает `frontend/mvp/api.js`; его базовый адрес изменён с `/api` на `/api/ui`. Раздельный сервер Node.js не запускается. CORS для локальной версии не требуется: HTML и API находятся на одном origin.

`app/routers/ui.py` переводит контракт дизайна в вызовы существующих доменных функций: `execute_payment`, `purchase_from_wallet`, управление приглашениями и планами. UI не вычисляет банковское подтверждение самостоятельно. Ошибки нового контракта имеют вид `{"error":{"code":"...","message":"..."}}`; формат исходных методов `detail` сохранён.

Все суммы — целые копейки. Валидаторы адаптера не принимают отрицательные, дробные, строковые суммы или bool. Отдельный `UiOperation` хранит полный отпечаток запроса и уникальную пару actor/key. Это предотвращает повтор с тем же ключом, но другим назначением, категорией, ребёнком или суммой. Успешные изменения денег выполняются исходным платёжным модулем в транзакции SQLite.

Запрос UI сохраняется до исполнения; итоговый результат читается из `Payment` или `ChildPurchase`. При потере связи `/operations/lookup` возвращает собственную операцию. Если запись результата в UI-конверт не успела сохраниться, адаптер ищет доменную операцию по тому же ключу. При отсутствии подтверждённого результата показывает pending и не выполняет новое списание автоматически.

История UI содержит одну запись на логическую операцию; парные строки бухгалтерского журнала перевода не становятся двумя расходами. Исходная история движений остаётся в Operation. Операции исходного API также отображаются, если они относятся к общим счетам или детскому кошельку; личные покупки партнёра не включаются.

Модели `MonthlyBudget`, `Note`, `Goal`, `SavedOffer`, `ReminderCategory`, `UiOperation` добавлены отдельно в ui_models.py. Цель ссылается на отдельный счёт, её saved читается из остатка счёта. Дублирующего самостоятельного денежного баланса в JSON нет.

Участие в семье проверяется сервером на защищённых запросах. Снимок неподключённого взрослого содержит его личный счёт и собственные приглашения; снимок ребёнка — только его кошелёк, лимит и историю. Правило смены лимита сохранено: оно не меняет баланс. Сервер ограничивает согласование собственного плана через адаптер даже при одном взрослом.

У новых ошибок версий есть CONFLICT/BUDGET_CONFLICT, которые уже понимает дизайн. Нулевые строки детского плана не создают фиктивные статьи и не требуют нулевых платежей. Идентификаторы существующих статей сохраняются при правке, чтобы не разрушать связанные оплаты и напоминания.

Согласие в новом потоке фиксируется событием shared_access_consent с версией учебных условий. Полноценный реестр юридических согласий и пересмотр исходного API необходимы перед промышленным использованием.

Старые технические страницы сохранены для разработчика. Ссылка на legacy.html в новом меню заменена ссылкой на /docs, чтобы не вести на неподключённый старый браузерный прототип.
