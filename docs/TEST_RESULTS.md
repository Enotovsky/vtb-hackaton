# Результаты проверки объединённой сборки

Среда проверки: Linux, Python 3.12, SQLite, Chromium 141 через Playwright 1.56. Это фактическая проверка в среде разработки. Отдельные прогоны на macOS, Windows, Safari и мобильных устройствах не выполнялись.

## Автоматические API проверки

Команда: `python -m pytest -q`.

74 теста: 43 исходных теста бэкенда и 31 интеграционный тест, включая параметризованные проверки.

Проверены входы и раздельные сессии, права семьи, закрытость личных данных, согласие в потоке UI, истечение и отзыв приглашений, запрет повторного входа по старому приглашению, версии бюджета и плана, согласование другим взрослым, сохранение нулевых строк, платежи, недостаток средств, имитация отказа, детский лимит, заморозка, строгие суммы в копейках, полный отпечаток платёжного запроса, параллельные повторы, конкурирующая оплата одного напоминания, ручная отметка, заметки, HTTPS-ссылки, накопительная цель, дополнительные счета, избранные предложения, сброс демо, отключение быстрых входов и восстановление связи UI-конверта с доменной операцией.

Число тестов не является оценкой процентного покрытия. Нагрузочное тестирование и аудит безопасности не проводились.

## Браузерный сценарий

Команда: `python tests/browser_smoke.py`.

Сервер запускается на свободном порту с временной SQLite. Проверены три независимых браузерных контекста: Александр, Мария, Макс. Последовательно выполнены приглашение и согласие, изменение общего бюджета, создание и согласование детского плана, оплата секции, карманные деньги, покупка ребёнка, сумма расходов, заморозка, общие заметки, перезагрузка страницы и отзыв доступа в открытой вкладке. Проверена отрисовка на ширине 390 и 1440 пикселей, собраны ошибки JavaScript. В успешном прогоне ошибок JavaScript не обнаружено.

API отдельно проверяет, что карманные деньги из напоминания являются переводом, закрывают напоминание и не попадают в расходы. ID UI-операции остаётся стабильным между pending и завершённым состоянием, что позволяет обновлять открытое окно результата.

## Что ещё нужно проверять перед пилотом

- Реальные устройства и браузеры, доступность с экранным диктором и клавиатурой.
- Большие истории операций и нагрузку на SQLite; переход на PostgreSQL и миграции.
- Падение процесса в каждой фазе платежа, автоматическое восстановление и банковскую сверку.
- Реальную авторизацию, защиту сессий, аудит всех исходных эндпоинтов, ограничения запросов.
- Возвраты, отмены резервов, возрастные переходы, полномочия законных представителей.

Тесты используют отдельные временные базы. Пользовательская data/family_bank.db в них не участвует. Возможное предупреждение Starlette о тестовом транспорте httpx является предупреждением библиотеки и не означает падения теста.
